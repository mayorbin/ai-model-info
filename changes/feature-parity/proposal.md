# Proposal: 补齐 ai-model-world 的页面级功能差距

## 背景

本项目（ai-model-info）的数据层与派生逻辑移植自 `D:\SourceCode\ai-model-world`，
但 UI 重写时只落地了三个页面（首页、模型详情、styleguide）。对照参考项目逐项盘点后，
确认以下页面与配套交互是参考项目有、本项目没有的「遗漏」，而非有意不采用的风格差异。

## 差距清单

参考项目有、本项目缺（本变更要补）：

| # | 参考项目 | 内容 | 本项目现状 |
|---|---|---|---|
| 1 | `/vendor/[id]` | 厂商详情页（65 家），按发布月份分组的全家桶 | 无任何 vendor 路由 |
| 2 | `/leaderboard` | 排行榜：智力/性价比/上下文/价格/30+ 编程赛制，含地区/开源/类型/退役筛选，筛选状态同步 URL query 可分享 | 无排行榜页面 |
| 3 | `/leaderboard/all` | 全部模型总表（可对照 #2 的分榜） | 无 |
| 4 | `/chronicle` | 发布时间线，月度分桶 | 无 |
| 5 | `/compare` | 模型对比：最多 4 个模型、localStorage 持久化、同成绩池才判胜负 | 无 |

参考项目有、本项目**有意不采用**（明确排除，不视为遗漏）：

- 像素小人/Q 版精灵图、家徽纹章、`/qa/crests` 校对页——本项目厂商身份由官方品牌 logo 表达；
- B 站视频嵌入与 toy 打包——非数据站核心；
- `scripts/sync` 上游同步管线——本项目是快照消费方，数据一次性移植；
- 英文 i18n、主题切换——两边都只有中文/深色，非差距。

两边都缺（不在本变更范围，留待后续）：sitemap/robots、feed、数据导出。

## 范围

**做**：上表 5 项，全部用现有数据（`data/models.json`、`src/data/*`、`src/lib/*` 派生层）实现，
UI 遵循 `DESIGN.md`（token、对比度、组件规则），交互逻辑参考
`ai-model-world` 对应模块后按本项目风格重写，不照搬像素风 JSX。

- 厂商页：logo 头部 + 品牌色左缘条 + 按发布月份分组模型列表 + 国内/国外归属 + 数据溯源；
- 排行榜：分榜切换 + 四维筛选 + URL query 同步（静态导出下用读取 query 渲染的客户端列表）；
- 总表：全模型平铺，含关键列，沿用筛选交互；
- 时间线：月度分桶 + 年份跳转锚点；
- 对比：模型选择器（接入现有 ⌘K 全局搜索的索引）、并排对照、胜负判定（同成绩池才判）、localStorage 记忆；
- 全站导航：现有组件补齐到新页面的入口（首页锚点导航 + 厂商卡片/排行榜行跳转）。

**不做**：见上「有意不采用」与「两边都缺」两节；不新增数据源文件；不动 `scripts/check` 的既有不变式（新增页面如果影响「N 个有成绩的模型」等口径，以 check 实际报错为准修正）。

## 验收标准

1. `npm run verify` 四项全过；
2. `npm run shots` 在 1440/390 两断点截图无横向滚动、字号可读；
3. 五个新路由全部出现在静态导出产物 `out/` 中，且 model 页的既有链接/锚点不回归；
4. 组件遵守 250 行目标/400 行硬上限（AGENTS.md 一）；
5. 对比页刷新后选择不丢（localStorage），排行榜筛选可经 URL query 复原。

## 风险

- **静态导出 + URL query**：参考项目同为静态导出，其 `useUrlQuery` 方案可直接借鉴，风险低；
- **页面数增长**：vendor 65 页加入 `generateStaticParams`，构建时间上升但可控（model 635 页已在跑）；
- **对比数据加载**：参考项目用 `/compare-data.json` 路由，本项目需改为构建期生成静态 JSON（参照 `search-index.json` 的做法）；
- **口径冲突**：新页面若引用「有成绩的模型」等口径，必须与 `check-consistency.ts` 的既有不变式一致，避免出现两个 N。
