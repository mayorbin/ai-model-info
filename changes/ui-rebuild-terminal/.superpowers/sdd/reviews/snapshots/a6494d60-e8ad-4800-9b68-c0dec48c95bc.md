### 缺陷修复（本批次自查发现）

**状态行与类型计数不一致。** 状态行原报 `snapshot.models.length`（635，含已退役），
而「按类型看」六个计数之和是在役数 617。两个数字同屏且不相等，读者会以为哪边算错了。
已改为报在役数，并把这条不变式写成 `check-consistency.ts` 的第 1 条检查。

### 交付后补修（第二轮审阅追加）

**验证命令的平台假设错误。** `workflow complete` 把 `--verification-command` 交给
`spawnSync(..., { shell: true })` 执行，在 Windows 上落到 `cmd.exe`，而原先写的
`NEXT_DIST_DIR=.next-build npm run build` 是 POSIX 环境变量前缀，直接报「不是内部或外部
命令」，验证被误判为失败。已新增 `npm run verify` 作为跨平台的单一验证命令，
并把「不要靠 shell 前缀传环境变量」写进 `AGENTS.md` 第三节。
**这类缺陷不看输出就会当成业务失败**，值得留档。

**导出目录判断错误。** 首轮曾断言「Next 16 覆盖 `distDir` 时导出产物落进 `distDir`、
不再生成 `out/`」，并据此把 `shots.ts` 与 `check-consistency.ts` 的默认目录改成 `.next`。
用默认 `distDir` 复跑后确认真相是：**默认写 `out/`，只有覆盖 `distDir` 时产物才落进
`distDir` 本身**。两个脚本的默认目录已改回 `out/`（`NEXT_DIST_DIR` 仍优先），
两条路径都验证可用。原 `tasks.md` 4.2 写的「指向 `out/`」本来是对的，
是首轮的「订正」把它改错了。

### 可访问性

- 装饰性元素（`VendorLogo`、状态灯、竖条、分隔点）一律 `aria-hidden`，
  避免读屏把首字徽章读成一个孤立字符。
- 导航当前项带 `aria-current="page"`；未实现的路由用 `aria-disabled` 且不可点，
  不产出指向 404 的坏链接。
- `MetricBar` / `Badge` / `SectionHeading` 的悬停解释挂在 `title` 上。

   上线前需要排除（加环境判断或移到构建外）。
2. **`src/lib/scores.ts` 当前零引用者（474 行）。** 它按 tasks.md 1.2 的计划移植，
   消费者是尚未实现的排行榜页。保留是有意的分阶段移植，不是遗漏；
   下一步做排行榜时直接可用。同类情况还有 `derive.ts` 的 `buildSizeScale`

3. **无页内锚点跳转。** 整页两区共 40 块，跳转会有用，但那属于新增需求。
4. **「最聪明是 Claude Opus 5.5、同一张卡片上编程显示偏弱」的观感问题。**
